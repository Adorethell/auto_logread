name: log_analysis
description: 用于分析 anomalies_merged 文件夹下的异常日志，并生成与示例风格一致的 HTML 报告。

instructions: |
  当用户要求对 `anomalies_merged` 目录下的日志进行分析时，请严格按照以下步骤执行，无需编写任何脚本，直接由你进行内容分析与报告生成。

  ## 1. 理解目录结构
  - 将 `anomalies_merged` 文件夹下的**每个一级子文件夹**视为一个独立的**测试单元（测试模组）**。
  - 测试单元文件夹下的**每个二级子文件夹**代表该模组**某一天的统计结果**。
  - 二级子文件夹内的**每个文件**代表当天发生的**一次异常事件记录**。

  ## 2. 异常文件分析流程
  对每一个异常文件执行以下操作：
  - 读取文件全部内容。
  - 提取核心异常信息，包括：异常类型、发生时间戳、关键错误描述或堆栈特征。
  - 识别并过滤重复信息、休眠数据等冗余内容，仅保留可用于定位问题的核心细节。

  ## 3. 数据汇总与记录
  - 为每个测试单元建立异常明细列表。
  - 明细列表需包含：异常文件名、异常发生时间、异常日志数据摘要、分析得出的异常原因。

  ## 4. 生成最终报告（严格参照示例）
  **参考范例路径：** `example/example.html`

  ### 输出要求：
  - **HTML 可视化报告**：
    - **代码结构与风格**必须与 `example/example.html` 完全一致（CSS 样式、布局、图表呈现方式等）。
    - 仅替换其中的数据内容（统计数字、异常列表、时间轴信息等）。
    - 确保用户可以直观浏览整体统计情况与每个异常的具体分析。

  ## 5. 文件保存位置
  - 在当前工作目录下创建 `claude_log_analysis` 文件夹。
  - 将生成的 `report.html` 保存至该文件夹内。

  ## 注意事项
  - **不要**编写 Python 或 Shell 脚本去处理文件，由你直接理解内容并构造输出。
  - 分析时必须忽略无关噪音，专注于异常核心特征。
  - 确保每次生成的 HTML 报告风格与示例保持高度一致，避免样式漂移。
